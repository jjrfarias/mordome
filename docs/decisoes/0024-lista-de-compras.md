# ADR 0024: Lista de compras

- Estado: aceito
- Data: 2026-09-15

## Contexto

O Estoque já permite cadastrar itens com `minimumStock`, dar entrada/ajustar/transferir saldo (`StockMovement`), planejar uma compra formal (`PurchaseOrder`/`PurchaseOrderItem`, ADR 0021) e registrar a chegada de mercadoria (`GoodsReceiptNote`, ADR 0020). Falta uma tela intermediária, mais informal, que responda "o que eu preciso comprar agora": hoje o dono precisaria olhar item por item em "Itens de estoque" para descobrir quem está abaixo do mínimo, e não há como anotar "quero comprar mais churrasco pro fim de semana" sem já abrir uma ordem de compra formal.

## Decisões

1. **Duas fontes combinadas na mesma tela, só uma delas persistida.** Sugestões automáticas (todo item configurado cujo saldo atual está abaixo do `minimumStock`) são calculadas em tempo real a cada consulta — não existe tabela nem cache para elas; assim que o saldo volta a ficar acima do mínimo (ex.: nota de entrada confirmada), a sugestão desaparece sozinha, sem nenhum código extra. Itens manuais (o usuário quer comprar algo específico, esteja ou não abaixo do mínimo) são persistidos em `ShoppingListItem`, pois representam uma intenção declarada pelo usuário que precisa sobreviver a reconsultas e ser distinguida das sugestões automáticas.
2. **Fórmula de sugestão: `minimumStock - balance`, arredondada para cima em 3 casas decimais** (`suggestedPurchaseQuantity` em `lib/inventory-domain.ts`). Arredondar para cima evita que uma sugestão fique tecnicamente abaixo do mínimo por causa de arredondamento; a granularidade de 3 casas acompanha a mesma precisão já usada em todo o módulo de estoque (`roundStock`). Decisão simples e sujeita a revisão futura caso o negócio precise de lotes/embalagens fixas por fornecedor (ex.: só vender saco de 25kg).
3. **`ShoppingListItem` com campo `resolved: boolean`, sem status complexo.** Só os itens manuais precisam de um ciclo de vida, e esse ciclo é binário: ativo (aparece na lista) ou resolvido (não aparece mais), seja porque virou ordem de compra ou porque o usuário descartou manualmente ("já providenciado"). Um enum de status maior (ex.: pendente/em ordem/comprado/cancelado) traria complexidade sem benefício real nesta fatia — a Ordem de compra gerada já tem seu próprio ciclo de vida rico (`DRAFT`/`SENT`/`RECEIVED`/`CANCELLED`, ADR 0021) que continua sendo a fonte de verdade sobre "a compra foi feita ou não". Se o negócio precisar rastrear itens manuais que geraram uma ordem cancelada e deveriam voltar à lista, isso é uma fatia futura (hoje o item manual usado para gerar uma ordem já cancelada permanece `resolved: true`, não retorna sozinho à lista — limitação conhecida).
4. **"Gerar ordem de compra" reaproveita a mesma sequência de operações de criação de ordem, nunca duplica a lógica.** No servidor, `POST /api/admin/inventory/shopping-list/generate-order` roda, dentro de uma única transação, exatamente a mesma sequência que a rota `/api/admin/inventory/purchase-orders` já faz em `CREATE_ORDER` + `ADD_ITEM` (criar `PurchaseOrder`, criar um `PurchaseOrderItem` por item selecionado, gravar `AuditEvent`), em vez de chamar a rota HTTP internamente (o que exigiria fetch interno ou reescrever autenticação) ou duplicar a lógica em outro arquivo. No modo local, a nova rota chama diretamente `createLocalPurchaseOrder`/`addLocalPurchaseOrderItem`, os mesmos usados por `lib/local-purchase-orders.ts`, através de uma função dedicada `generateLocalPurchaseOrderFromShoppingList` em `lib/local-shopping-list.ts`. O custo estimado de cada item nasce zerado (`estimatedUnitCost: 0`) — a Lista de compras não tem preço, só quantidade; o valor é preenchido depois na tela de Ordem de compra já existente.
5. **Itens manuais selecionados na geração da ordem são marcados `resolved: true` no mesmo passo.** Isso evita que um item manual já convertido em ordem continue aparecendo indefinidamente na lista ativa. Sugestões automáticas selecionadas não têm registro próprio (não existe uma linha para marcar como resolvida) — elas somem sozinhas quando o saldo sobe, conforme decisão 1; nenhuma ação adicional é necessária para elas após gerar a ordem.
6. **Permissão reaproveitada: `stock.manage`.** A mesma permissão que já controla os demais cadastros de estoque (itens, ordens de compra, notas de entrada) controla a Lista de compras — não é uma operação de ajuste de saldo (não usa `stock.adjust`), é planejamento/cadastro.
7. **API usa o mesmo padrão de `action` via POST já estabelecido no módulo, não verbos HTTP RPC-style (PATCH).** Todas as rotas de estoque desta branch (`/api/admin/inventory`, `/api/admin/inventory/purchase-orders`) usam um único `POST` com campo `action` discriminando a operação, validado por `zod.discriminatedUnion`. A Lista de compras segue o mesmo padrão (`ADD_ITEM`/`UPDATE_ITEM`) para manter consistência com o restante do módulo, em vez de introduzir um método `PATCH` isolado.
8. **Interface: nova sub-aba "Lista de compras"** dentro de Estoque, ao lado de "Itens de estoque", "Ordens de compra", "Notas de entrada" e "Contagem de estoque". Sugestões automáticas usam o mesmo destaque visual `.low`/"Estoque baixo" já usado em "Itens de estoque". Cada linha (sugestão ou manual) tem uma caixa de seleção; um cabeçalho fixo mostra quantos itens estão selecionados, permite escolher um fornecedor opcional e tem o botão "Gerar ordem de compra". Itens manuais têm um botão "Já providenciado" que marca `resolved: true` sem precisar gerar ordem.

## Consequências

- Nenhuma tabela nova para as sugestões automáticas — elas são sempre um retrato atual do saldo, nunca ficam desatualizadas nem precisam de rotina de limpeza.
- `ShoppingListItem` é a única tabela nova desta fatia, com ciclo de vida deliberadamente simples (booleano).
- A criação de `PurchaseOrder` continua tendo uma única lógica de verdade por camada (servidor e local), agora chamada tanto pela tela de Ordens de compra quanto pela Lista de compras.
- Pendência explícita para decisão humana / fatia futura: itens manuais cuja ordem gerada é depois cancelada não retornam automaticamente à lista ativa — o usuário precisaria adicioná-los de novo manualmente se ainda quiser comprá-los.
